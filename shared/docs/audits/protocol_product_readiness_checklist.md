# Protocol Product Readiness Checklist

A protocol is only considered buyable and usable when all items below are satisfied.

## 1. Product Definition
- [ ] manifest.yaml exists
- [ ] product title is clear
- [ ] summary is commercially understandable
- [ ] supported countries are listed
- [ ] supported use cases are listed
- [ ] risk level is defined
- [ ] required capabilities are listed
- [ ] deliverables are listed
- [ ] commercial tier is defined

## 2. Protocol Logic
- [ ] base policy exists
- [ ] role rules exist where applicable
- [ ] country overlays exist
- [ ] safety overrides exist
- [ ] logic is internally consistent
- [ ] no prohibited behavior is implied

## 3. Buyer Documentation
- [ ] product_page_copy.md exists
- [ ] limitations.md exists
- [ ] compatibility.md exists
- [ ] README.md explains what is included
- [ ] deployment expectations are clear
- [ ] human supervision requirements are clear

## 4. Testing
- [ ] scenarios.yaml exists
- [ ] acceptance_criteria.yaml exists
- [ ] tests reflect actual product use cases
- [ ] safety/privacy conditions are covered

## 5. Marketplace Readiness
- [ ] listing JSON exists
- [ ] listing price is defined
- [ ] card subtitle is commercially clear
- [ ] best_for list is relevant
- [ ] product is included in protocol catalog
- [ ] sales mode is defined

## 6. Commercial Integrity
- [ ] no fake compatibility claims
- [ ] no fake automation claims
- [ ] no implied capabilities not included in files
- [ ] limitations are explicitly stated
- [ ] product can be delivered as a real asset

## Final Status
- Spec-only
- Product-ready
- Marketplace-ready
