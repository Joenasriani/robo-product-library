# Readiness Model

The Robotics Buyer Readiness Wizard evaluates whether a facility has enough operational, technical, safety, and staffing maturity to begin a robot purchase/deployment discussion.

## Scoring dimensions

| Dimension | Purpose | Example evidence |
|---|---|---|
| Facility fit | Checks whether the facility type and use case are appropriate for the robot category. | Floor plan, zone list, service route description |
| Access readiness | Checks routes, elevators, doors, ramps, docks, and restricted zones. | Elevator policy, access control process |
| Human traffic | Checks congestion, peak periods, children/guest exposure, and staff interaction points. | Peak-hour schedule, lobby/corridor density notes |
| Connectivity | Checks Wi-Fi, LTE/5G fallback, dead zones, and network ownership. | Coverage map or IT confirmation |
| Operations support | Checks whether staff can monitor, escalate, recover, and maintain the robot. | Operator owner, escalation contacts, SOP owner |
| Safety governance | Checks whether a human safety owner and incident process exist. | Safety review owner, incident log owner |
| Budget realism | Checks whether buyer expectations match deployment cost uncertainty. | Approved budget range or procurement stage |

## Readiness levels

- `not_ready` — major blockers prevent responsible vendor matching.
- `needs_preparation` — buyer has a valid use case but must fix gaps first.
- `pilot_ready` — buyer can start a limited pilot discussion.
- `deployment_candidate` — buyer has enough information for vendor/integrator review.

## Human review requirement

The score is not a certification. Any deployment plan must be reviewed by a qualified robotics integrator, facility operator, and safety owner before real robot use.
